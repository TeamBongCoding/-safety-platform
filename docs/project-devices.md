# 프로젝트 임베디드 장치 구성

## 1. 문서 목적

이 문서는 AI 안전관리 플랫폼을 실제 현장 또는 데모 환경에서 구동하기 위해 필요한 임베디드 장치와 주변 장비를 정리한다.

현재 프로젝트는 크게 다음 두 부분으로 구성된다.

1. 카메라 영상을 이용해 작업자, 안전모 착용 여부 및 위험구역 접근을 판정하는 영상 분석 시스템
2. 안전고리의 개폐 및 체결 지점을 확인하고 작업자에게 진동 경고를 전달하는 ESP32 기반 착용형 장치

현재 저장소에는 ESP32 실제 펌웨어가 없으며, `backend/scripts/harness_sim.py`가 장치의 동작을 대신 시뮬레이션한다.

## 2. 실제 현장 구축에 필요한 필수 장치

| 구분 | 필요한 장치 | 수량 기준 | 역할 |
|---|---|---:|---|
| 영상 수집 | CCTV, IP 카메라 또는 USB 카메라 | 감시 구역당 1대 이상 | 작업자와 안전모를 촬영한다. |
| AI 연산 | GPU 탑재 PC 또는 엣지 AI 컴퓨터 | 현장당 1대 이상 | YOLO 추론과 위험구역 판정을 수행한다. |
| 착용형 제어기 | Wi-Fi 지원 ESP32 보드 | 작업자당 1개 | 안전고리 상태를 서버에 전송하고 경고 명령을 수신한다. |
| 고리 개폐 감지 | 리미트 스위치, 리드 스위치 또는 홀 센서 | 안전고리당 1개 | 안전고리가 닫혔는지 감지한다. |
| 체결 지점 인식 | RFID/NFC 리더 모듈 | 작업자당 1개 | 고리가 승인된 체결 지점에 연결되었는지 확인한다. |
| 체결 지점 식별 | 방수형 패시브 RFID/NFC 태그 | 체결 지점당 1개 | 체결 지점의 고유 ID를 제공한다. |
| 작업자 경고 | 진동 모터 | 작업자당 1개 | 위험구역 접근, 안전모 미착용 또는 안전고리 미체결을 경고한다. |
| 모터 구동 | 트랜지스터 또는 MOSFET 모터 드라이버와 보호 다이오드 | 작업자당 1세트 | ESP32 출력으로 진동 모터를 안전하게 구동한다. |
| 휴대 전원 | 충전식 배터리 | 작업자당 1개 | 착용형 장치에 전원을 공급한다. |
| 전원 관리 | 충전·보호 회로 및 전압 레귤레이터 | 작업자당 1세트 | 배터리 충전, 과방전·과전류 방지 및 안정적인 전압 공급을 담당한다. |
| 무선 통신 | Wi-Fi 공유기 또는 산업용 무선 AP | 현장당 1대 이상 | ESP32, 분석 서버 및 관리자 화면을 연결한다. |
| 데이터 저장 | SSD | 서버당 1개 | 영상, 이벤트, AI 모델 및 데이터베이스를 저장한다. |
| 장치 보호 | 방진·방수 케이스, 커넥터, 배선 및 PCB | 착용 장치당 1세트 | 충격, 먼지 및 수분으로부터 회로를 보호한다. |

카메라와 무선 AP의 실제 수량은 현장의 면적, 사각지대, 벽과 장애물, 동시 접속 작업자 수를 기준으로 결정해야 한다.

## 3. 영상 분석 장치

### 3.1 카메라

영상 분석 시스템에는 다음 중 하나가 필요하다.

- USB 카메라: 가까운 거리의 단일 카메라 데모에 적합하다.
- IP 카메라: RTSP 스트림을 이용하는 현장 설치에 적합하다.
- 기존 CCTV: RTSP 또는 영상 파일을 분석 서버에서 받을 수 있는 경우 활용할 수 있다.

카메라는 다음 조건을 고려해 선택한다.

- 작업자의 머리와 전신을 함께 식별할 수 있는 해상도
- 역광과 저조도 환경에 대응할 수 있는 성능
- 움직이는 작업자를 식별할 수 있는 프레임 속도
- 실외 설치 시 방진·방수 등급
- 유선 네트워크 또는 안정적인 무선 연결

현재 영상 분석 스크립트는 MP4 파일을 입력으로 사용한다. 실제 카메라를 연결하려면 USB 카메라 인덱스 또는 IP 카메라의 RTSP 스트림을 입력으로 처리하도록 별도 연동이 필요하다.

### 3.2 AI 연산 장치

`backend/app/services/detector.py`는 안전모 판정 모델과 사람 감지 모델을 각각 실행한다. 따라서 ESP32와 같은 마이크로컨트롤러에서 영상 분석을 직접 수행할 수 없으며, 별도의 AI 연산 장치가 필요하다.

구축 단계별 권장 형태는 다음과 같다.

| 환경 | 연산 장치 형태 |
|---|---|
| 해커톤 또는 기능 데모 | 기존 노트북이나 데스크톱 |
| 소규모 현장 | NVIDIA GPU가 장착된 미니 PC |
| 독립형 엣지 시스템 | Jetson 계열과 같은 엣지 AI 컴퓨터 |
| 다수 카메라 현장 | 별도 GPU 서버 또는 카메라별 엣지 연산 장치 |

AI 연산 장치는 카메라 입력 수, 목표 FPS, 영상 해상도 및 동시 실행 모델 수를 기준으로 선정해야 한다.

## 4. ESP32 작업자 착용 장치

작업자 한 명당 기본 구성은 다음과 같다.

```text
안전고리 개폐 센서 ─┐
                    ├─ ESP32 ─ Wi-Fi ─ FastAPI 서버
RFID/NFC 리더 ──────┘    │
                         └─ 모터 드라이버 ─ 진동 모터
```

서버가 장치로부터 요구하는 상태 데이터는 다음과 같다.

| 필드 | 의미 |
|---|---|
| `device_id` | 작업자 또는 착용 장치를 구분하는 ID |
| `hook_closed` | 안전고리가 닫혀 있는지 나타내는 값 |
| `rfid_tag` | 현재 인식된 체결 지점의 RFID 태그 ID |

서버는 다음 조건을 모두 만족할 때만 정상 체결로 판단한다.

1. 고리 개폐 센서가 닫힘 상태를 보고한다.
2. RFID/NFC 리더가 체결 지점의 태그를 읽는다.
3. 읽은 태그가 서버의 승인된 태그 목록에 포함되어 있다.

서버 응답의 `vibrate` 값이 `true`이면 ESP32는 모터 드라이버를 통해 진동 모터를 작동시켜야 한다.

### 4.1 고리 개폐 센서 선택

- 리미트 스위치: 구조가 단순하지만 기계적 접촉과 마모가 발생한다.
- 리드 스위치: 자석을 이용하므로 비접촉 감지가 가능하지만 충격에 주의해야 한다.
- 홀 센서: 비접촉 방식이며 반복 사용에 적합하지만 자석과 안정적인 전원 설계가 필요하다.

실제 안전고리의 기계적 구조를 변경하면 강도와 인증에 영향을 줄 수 있으므로, 센서는 하중을 받지 않는 보조 위치에 설치해야 한다.

### 4.2 RFID/NFC 구성

RFID/NFC 리더는 착용 장치 또는 안전고리 측에 설치하고, 패시브 태그는 승인된 체결 지점에 설치한다. 태그는 다음 조건을 만족해야 한다.

- 체결 동작 중 안정적으로 인식되는 거리
- 금속 구조물에 설치할 경우 금속 대응형 태그 사용
- 실외 또는 분진 환경에 적합한 내구성과 방수 성능
- 체결 지점마다 고유한 태그 ID 부여

RFID 태그는 고리의 닫힘 여부를 직접 증명하지 않는다. 따라서 개폐 센서와 RFID 리더를 함께 사용해야 한다.

### 4.3 진동 모터 구동

ESP32 GPIO에 진동 모터를 직접 연결하면 안 된다. 모터 전류를 처리할 수 있는 트랜지스터 또는 MOSFET 드라이버를 사용하고, 유도성 부하에 대한 보호 다이오드를 구성해야 한다.

진동 경고는 다음과 같이 구분할 수 있다.

- 짧은 단발 진동: 서버 연결 또는 상태 확인
- 반복 진동: 위험구역 접근 경고
- 빠르고 강한 반복 진동: 위험구역 진입 또는 보호구 미착용 경고

현재 서버는 진동 여부만 Boolean 값으로 반환하므로, 진동 패턴을 세분화하려면 API에 경고 단계 또는 패턴 정보를 추가해야 한다.

## 5. 전원 구성

착용형 장치에는 다음 전원 부품이 필요하다.

- 충전식 리튬이온 또는 리튬폴리머 배터리
- 과충전, 과방전 및 과전류 보호 회로
- USB 또는 전용 충전 모듈
- ESP32 및 RFID 리더에 맞는 전압 레귤레이터
- 전원 스위치
- 배터리 잔량 측정 회로

배터리 용량은 ESP32의 Wi-Fi 송신 주기, RFID 리더의 소비전력, 진동 모터의 동작 시간 및 목표 근무시간을 기준으로 산정해야 한다. 현재 시뮬레이터는 1초마다 서버에 상태를 전송하므로 실제 장치도 같은 주기를 사용하면 소비전력이 증가할 수 있다.

## 6. 네트워크 및 현장 인프라

ESP32 장치와 서버는 HTTP 통신을 사용하므로 동일 네트워크 또는 상호 접근 가능한 네트워크가 필요하다.

기본 네트워크 구성은 다음과 같다.

```text
IP/USB 카메라 ─┐
               ├─ 유·무선 네트워크 ─ AI 분석 서버 ─ 관리자 웹 화면
ESP32 장치들 ──┘
```

현장 네트워크에는 다음 장치를 사용할 수 있다.

- 일반 Wi-Fi 공유기: 소규모 실내 데모
- 산업용 무선 AP: 넓은 현장 또는 다수 작업자
- PoE 스위치: 여러 IP 카메라에 네트워크와 전원을 함께 공급
- LTE 라우터: 유선 인터넷이나 현장 Wi-Fi가 없는 경우
- UPS: 서버, 네트워크 장치 및 카메라의 정전 대비

작업자의 이동 경로 전체에서 Wi-Fi 음영 구역이 발생하지 않도록 AP 위치와 수량을 설계해야 한다.

## 7. 권장 추가 장치

다음 장치는 필수는 아니지만 현장용 제품의 신뢰성과 사용성을 높인다.

| 장치 | 목적 |
|---|---|
| 피에조 부저 | 작업자가 진동을 느끼지 못하는 경우 음향 경고를 제공한다. |
| 고휘도 LED 또는 RGB LED | 전원, 네트워크, 체결 및 경고 상태를 표시한다. |
| 테스트 버튼 | 작업 시작 전에 센서와 경고 장치가 정상인지 확인한다. |
| 배터리 잔량 측정 회로 | 방전 전에 작업자와 관리자에게 알린다. |
| 하드웨어 워치독 | ESP32 프로그램 정지 시 자동으로 복구한다. |
| 로컬 플래시 또는 SD 카드 | 통신 장애 시 상태와 이벤트를 임시 저장한다. |
| 비상 경광등 또는 사이렌 릴레이 | 현장 전체에 긴급 상황을 알린다. |

| 온도 센서 | 배터리 및 밀폐 케이스의 과열을 감시한다. |

## 9. 실제 장치 구현 시 추가 개발 항목

현재 저장소에는 ESP32용 펌웨어가 포함되어 있지 않다. 실제 장치를 제작하려면 다음 기능을 별도로 구현해야 한다.

1. 고리 개폐 센서 입력과 디바운싱 처리
2. RFID/NFC 태그 읽기
3. Wi-Fi 연결과 자동 재접속
4. 장치 ID 관리
5. 서버 상태 API로 주기적인 HTTP 요청 전송
6. 서버 응답에 따른 진동 모터 제어
7. 서버 또는 네트워크 장애 감지
8. 통신 실패 시 로컬 경고와 재전송
9. 배터리 잔량 측정 및 저전압 경고
10. 펌웨어 오류 복구를 위한 워치독
11. 장치 설정과 펌웨어 업데이트 방식

또한 현재 분석 코드와 FastAPI 서버를 서로 다른 프로세스로 실행하면 메모리에 저장된 경고 상태가 공유되지 않는 구조적 제약이 있다. 실제 ESP32 진동 경고를 안정적으로 전달하려면 경고 상태를 데이터베이스나 Redis와 같은 공용 저장소에 보관하거나, 영상 분석 파이프라인과 API 서버를 하나의 프로세스로 통합해야 한다.

## 10. 안전 및 제품화 주의사항

이 시스템은 영상 인식과 전자 센서를 이용한 안전 보조 시스템이며, 법정 안전장비나 작업자의 안전 절차를 대체하지 않는다.

- 안전벨트, 랜야드, 훅 및 체결 설비는 산업안전 규격을 충족하는 인증 제품을 사용해야 한다.
- 센서 설치를 위해 안전고리의 하중 지지 구조를 가공하거나 약화해서는 안 된다.
- 착용형 장치는 작업자의 움직임, 비상 탈출 및 장비 사용을 방해하지 않아야 한다.
- 배터리와 회로는 충격, 수분, 먼지, 금속 분진 및 고온 환경을 고려해 보호해야 한다.
- AI 오검출, 카메라 사각지대, 네트워크 장애 및 배터리 방전을 전제로 한 안전 절차가 필요하다.
- 실제 현장 도입 전 전기적 안전성, 무선 통신 안정성, 기구 내구성 및 관련 인증을 검토해야 한다.
